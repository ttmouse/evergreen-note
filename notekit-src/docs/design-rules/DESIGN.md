## §1 视觉语言与定位

**主张**【项目】：让多篇笔记同一工作区像一组连续、可比较的阅读材料——**一张连续的纸面，以细线和留白组织成多个阅读列**。内容优先，容器退后：界面本身不比内容更醒目。【基础】工具类产品克制优先。
**适用条件**：Notekit 桌面端 Andy Mode 多栏阅读/编辑区；其余界面共用 token 语义但布局规则仅 Andy Mode 适用。
**判定方式**：缩小或模糊界面看一眼——视觉焦点应先落在笔记标题与正文，而非容器轮廓。
**反例**："卡片墙"——每篇笔记独立边框/阴影/圆角/灰底并排。
**忌讳**：大面积强调底色、装饰性容器堆叠、AI 生成风套路（见 §2 禁用清单）。

## §2 UI 禁用清单（负向规则，最高优先，冲突时压过本规范其他条款）

**禁止**：「圆角浅色底块 + 左侧强调色竖条」组合用作导航/列表/当前项的默认状态表达。
- **来源**：2026-10-03 用户对侧栏"豆爸的知识体系"条目的截图反馈，明确列为禁技。
- **适用边界**：禁的是该组合**及其等价变体**——换颜色、改圆角大小、竖条从阴影换边框，都算复用。不禁止圆角、背景色、分隔线本身。
- **替代取舍**：保持平面列表，状态用文字颜色、字重或既有文字标记表达；不能以"克制"为由让交互状态消失——当前项仍须可辨认，键盘焦点反馈必须保留。
- **复查范围**：仓库自带样式与运行时已加载样式；用户笔记自定义 CSS、第三方嵌入页面不据此修改。2026-10-03 全面复查已完成一轮（引用块灰底+圆角+左竖条、回收站金色左边条已清）。
- **判定方式**：人工（grep 结构性组合 + 截图目检，浅色与夜间都看）。
- 登记：project-ledger 无独立 D 号，本条〔已并入正本〕后引用一律指向 §2。

## §3 Andy Mode 交互规则

**导航模型**：列位置表达阅读路径——左 = 当前阅读上下文，右 = 从该上下文展开的内容。
1. **点击朴素链接**：来源留原位，目标紧邻右侧打开或切换；不替换来源，不跳回主区。目标右侧已有阅读路径时，切换为新目标并收起旧路径（只关视图，不删数据），不能点一次堆一篇。
2. **右侧继续点击**：沿路径 continue 向右展开，形成左→右链（A→B→C）。依据：用户 2026-10-03 明确要求（D-006 superseded 前版本已修正）。
3. **新 vs 复用**：目标已在来源右侧 → 保留目标列、收起其余后续路径；目标在来源本身或左侧 → 聚焦已有列，不建重复列。点击针对**链接所在的那一篇笔记**，不是无条件最左列。
4. **多步导航一致性**：键盘打开、链接点击、"在右侧打开"命令遵循同一来源锚点规则，不同入口不得产生相反结果。
5. **阅读位置**：点击已可见目标不自动居中；超出阅读区只滚动到最近可见边界，左侧叠放脊柱计入可用宽度。保留减少动态效果设置。
6. **页面级导航替换当前列**：侧栏页面导航（每日/主题/图谱等注册页面，非笔记条目）点击后**当前活动列让位**：目标未开 → 关活动列，目标页在同位打开；目标已是列（含折叠）→ 活动列让位关闭，聚焦已有页，不重建不新增。页面不是阅读路径的一环，不适用 1–3 的右侧子列语义。依据：用户 2026-10-06 明确要求“点击主题应该替代当前笔记区域”（已开场景的让位语义由用户复测反馈定准）。
- **锚点依据**：“右侧打开”是阅读模式默认导航方式，列顺序持续表达当前路径（而非窗口堆积）。同一来源点击切换右侧内容是用户 2026-10-03 显式要求。
- **判定方式**：**人手走真实点击链路**（A→B→C→回 A 点 D→得 A/D→B 点另一目标→仅替换 B 右侧）；重复点击同一目标不出空列/重复列。富文本链接的真实点击才算通过，直接调用导航命令不算。
- **例外归属**：显式新增列、重排是独立操作，不受上述导航逻辑约束。

## §3a 排版（2026-10-05 补，如实记现状 + 建议目标待拍板）

【基础】层级靠字号与墨色，不靠加粗堆叠。
**现状分布**（实测两文件）：16px ×24、18px ×13、14px ×8、12px ×9、13px ×4、17/15/10px 各 1–2、24/28px ×2、34px ×1；另 all-styles 里有 rem 混用（.5625/.65625/.75rem）与百分比字号（75/80/85%），后者属旧层遗留。
**已确认的稳定层级**：正文 15–16px；分组标题/标注 12–14px；微注脚 10–12px。
**档位（2026-10-05 豆皮拍板定档）**：8 档 `{ 12, 13, 14, 16, 18, 24, 28, 34 }`——15px 并 16、17px 并 16（标题字级应与正文拉开）、10px 并 12（微注脚 10px 可读性在纸色底勉强，12px 更稳）；28px 保留（.srs-no-items 空态提示，×2 在用，阶位在 24 与 34 之间合理）。rem/百分比层随 all-styles 清欠处理，迁移时换算为 px 一手归档。
**数字排版**：本项目无 `tabular-nums`——时码、计数、图谱数字右侧排序场景，迁移档位时应同步给数字容器补上（与 shuangping/RTC 惯例对齐）。
**字体族**：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC"` 栈为正本，不引外部字体。
**判定方式**：人工目检 + 全量 grep font-size。

## §4 颜色与 token

**语义 token 是唯一契约**【基础】颜色一律经变量引用，不写裸 hex。
| 用途 | 语义角色 | 约束 |
|---|---|---|
| 工作区底色 | `--nk-canvas` | 优先统一，避免列列不同底色 |
| 笔记底色 | `--nk-surface` | 笔记表面，与 canvas 区分（D-006 已拍板两色制：画布/笔记） |
| 分隔线 | `--nk-line` | 低对比度、细线；**不得用整片灰背景模拟线条** |
| 标题正文 | `--nk-ink` | 保证主题正文对比度 |
| 次级信息 | `--nk-muted` | 只承担辅助，不承担正文可读性 |
| 当前焦点 | `--nk-accent` / `--nk-accent-soft` | 少量语义化使用，不把整列染成强调色 |

- **色值唯一来源（契约层）**：`notekit-src/src/assets/workspace-theme.css`（主题语义来源）。正本不复制色值。
- **颜色来源分层与归属**（2026-10-05 补，据 audit-2026-10-05 第一节；现状五层，逐层定归属，非契约层禁止扩张）：
  1. `--nk-*`（workspace-theme.css，18 定义/149 引用）——**契约层**，工作区界面唯一颜色语义来源。
  2. 旧通用名（:root `--primary`/`--info`/`--bgrey`/`--common-border` 等 14 个）——**桥接别名**，只改值不删行（all-styles 旧层有同名词旧值，删行会漏色），批次迁完即删（本节收欠条款）。
  3. `src/slate-item/addons/NightMode/NightMode.tsx` 运行时注入 `--dark-*`（20 定义 + 92 处 `!important` + 69 处消费）——**待收编过渡层**：与 `--nk-*` 职责重叠（同为夜间配色），且已是失效双源——`body.night-mode` 同名定义优先级更高，实际生效的是 workspace 版值，NightMode 版值不生效但仍在被读（audit 第二节）。规则：**禁止新增** `--dark-*` 定义与引用；收敛目标 = NightMode 定义块删除改读 `--nk-*`，映射建议 `--dark-bg-primary→--nk-canvas`、`--dark-bg-secondary→--nk-sidebar`、`--dark-text→--nk-ink`、`--dark-text-less-important→--nk-muted`、`--dark-important` 系→`--nk-hover` 档【待拍板】；死变量 `--bg-color`/`--body-bg-color`/`--dark-text-no-important` 一并清（工程侧）。
  4. all-styles.css 453 处裸 hex——**旧遗留层**，随 token 清欠批次收敛（该线挂起中，本条只登记归属，不构成启动）。
  5. `src/slate-item/styles/theme.ts` 色板（Ant 风格 ColorBase×Depth，143 处色值）与 `--cl-{base}-{depth}` 变量——**项目自治层**：编辑器内组件与插件（Form/Background/Backlink/Clue/Embedweb 等）的专用色板，正本只登记边界、不约束值。边界规则：工作区 chrome 样式（workspace-theme 及未来 chrome 类）不得引 `--cl-*`；`--cl-*` 不得用于导航/标签/画布等工作区界面语义；旧层交叉类（mark-tag、MDTable 等内容渲染类）随清欠批按「内容组件归 cl 域、工作区界面归 nk 域」归类，判定归设计。
- **主题策略**：浅色 / 夜间**双主题都必须实现**（与 RTC 不同——本产品是长时间阅读工具，夜间是正式主题之一）。深色主题须使用对应暗色语义线色，不得沿用浅色硬编码。核心判断：某处看起来只在浅色下对 → 大概率有硬编码残留。
- **收欠**：旧通用名（`--primary`/`--info`/`--bgrey`/`--danger`…）降级为 `var(--nk-*)` 别名做过渡；**别名只做过渡不做长期**，每个批次迁完顺手删该别名，不制造新债。新代码一律只用 `--nk-*`。
- **判定方式**：可跑静态 grep（裸 hex、旧通用名引用计数），与验收相连。

### §4.5 组件逐态（2026-10-05 补：现状基线 + 目标待拍板；T4 清 `!important` 的判定依据）

**主张**【项目】：工作区界面组件（导航行、标签页、按钮、输入框、对话框/浮层）的交互状态用统一的逐态语义表达，浅色/夜间双主题都完整实现；状态底色一律走 `--nk-hover` / `--nk-tab-hover`，不写裸值。

**逐态定义与现状基线**（实测 workspace-theme.css，2026-10-05）：

| 态 | 现状基线 | 目标（待拍板） |
|---|---|---|
| default / 选中 | 选中/当前项以 `.is-active` 类 + 文字色/字重等**单信号**表达（`tab.is-active`、`search-result-item.active`），禁多信号叠加（承 §2 替代条款与 §7） | 维持单信号原则 |
| hover | **已 token 化**：`--nk-hover`（浅 `rgba(0,0,0,.045)` / 夜 `#304148`）约 20 处引用，`--nk-tab-hover` 专用于标签页；残留个别裸值（:46 backlink `rgba(0,0,0,.05)`） | 裸值随清欠批归 `--nk-hover`/`--nk-tab-hover` |
| active(pressed) | 仅 1 处（:47 `rgba(0,0,0,.1)`），无 pressed 语义 token | 不立新 token：归并 hover 加深一档或个案保留【待拍板】 |
| focus-visible | 25 处规则，**环样式三种并存**：`outline 2px` 色＝`--node-text-link` / `--nk-muted` / 裸值（浅 `#6c99a5`、夜 `#8fb9c4`），offset 2/−2/3 不一 | 统一 2px outline + offset 2；环色立 `--nk-focus-ring` 或归 `--nk-accent`【待拍板】；NightMode 注入层 0 焦点规则是已知缺口（audit 第五节），随暗色收敛批次补齐 |
| disabled | 主题层 0 规则（all-styles 仅 1 处），现状浏览器默认降灰 | 暂不立规则；清欠中发现影响可用性再立【待拍板】 |

**适用条件**：工作区界面（§1 适用范围）；编辑器内组件（`--cl-*` 域，§4 分层第 5 项）逐态不归本节，由组件库自治。
**反例**：同层级控件 hover 一处 token 一处裸 rgba；同一主题内 focus 环三种色；夜间控件键盘聚焦不可见（NightMode 层现状）。
**判定方式**：浅色/夜间双主题逐态截图（接 §8 第 6/7 条）+ grep `:hover|:focus-visible|:active` 计数。
**起因**：audit-2026-10-05 第四节「正本缺组件逐态节」；T4（清 `!important` 193 处）需要本节作判定依据，没有它只能凭眼。

## §5 布局与档位（2026-10-05 扩充：档位表，作收欠判定依据）

【项目】Andy Mode：
- **列宽**：桌面列 625px、正文左右 32px、标题条 40px（D-006/D-007 已拍板）；横向空间不足时滚动叠压露竖标题；800px 以下显示活动单篇。
- **分割线**：只落在相邻边界，不形成灰底板或外围框线；不得与容器边框重复叠加。顶部导航与正文有横向 1px 分割线。
- **列滚动区域彼此独立**；隐藏非活动列滚动条不得裁切内容或丢位置。
- **顶部标签/工具区应轻量**：与正文层级清楚，视觉重量低于笔记内文，不得像另一层厚重卡片。
- 列数增加时，优先保持阅读边界与焦点识别，不以加装饰补偿信息密度。

### §5.1 圆角档位表（2026-10-05 修订：如实修订前提）

**实测修正**：--radius-sm(2px) 用量 0 的早期前提不成立——2px 实有 6 处（workspace 1 + all-styles 5）。`--radius--*` 系列对业务代码**基本无影响**：全项目 `var(--radius*)` 引用仅 1 处（全 all-styles 里的 `var(--radius-lg)`），token 定义了没人用，裸值在用。

**优先问题不是收档位，而是"要不要用 token"**——token 定了没引用，改定义也是空转。**豆皮拍板：先启用 token**（`--radius*` 定义了几乎无人用是根本问题），散值随清欠批迁移。执行分两步：
1. **先决定用哪套 token**（`--radius*` 已存在，建议保留并启用，新代码引用 token；旧代码随清欠批渐进迁移）；
2. **再按用例修档位**：若启用现有 token，建议目标 `{ 2px(sm), 3px(sm), 4px(radius/md), 8px(lg), 9999px(pill) }`，`--radius-md` 与 `--radius` 重复无意义，**md 重定义 4→6**、sm 保持 2px 不是重定义问题，是旧值怎么归档问题。

| 建议档 | token 承接 | 现状分布 | 收敛动作 | 依据 |
|---|---|---|---|---|
| 2px | --radius-sm（**拍板保持 2px 不重定义**） | 2px ×6 | 维持定义不变，散 2px 归 sm | 2px 有真实用量，**不重定义** |
| 3px | —（不立 token） | 3px ×2 | 归 2px 或 4px（**拍板：个案判定**，量太小） |
| 4px | --radius / --radius-md | 4px ×8 | md 与 radius 重复，md 保留别名最终删 | 用量最大者保本值 |
| 6px | --radius-md（**拍板重定义 4→6**） | 6px ×8 | md 改 6，散 6 归 md | 6px 实际是主力 Control 档，token 却没这个值 |
| 8px | --radius-lg | 8px ×5（全项目）、9px ×2（workspace）、10px ×5（workspace 3 + all-styles 1 + addon-center 1） | 9/10 归 8 | lg 已是 8；9/10 是无 token 时代散值，口径统一全项目含 addon 侧样式 |
| 胶囊 | --radius-pill: 9999px（**拍板新增**） | 100px ×20、9999px ×2 | **拍板：新增 token**，100px 归 9999 | **修正依据**：100px 在 aspect-ratio:1/1 小按钮上完全够用（实测 19 处均为小尺寸），"失效"不成立——统一 9999 的理由是**减少一种记忆与非熟练录入时的不适当值**，1 个非档位值收敛为全统一 |
| 0 | 不立 token | 0 / unset ×4 | 保留原样 | 特例场景，非档位 |

## §6 交互与动效

- **动效只解释变化**：打开/切换/重排时列边界与阅读位置稳定；不制造卡片飞入、弹跳等装饰动效。
- **遵循系统减少动态效果设置**（`prefers-reduced-motion`），基础层惯例。
- **单反例警示**：Andy Mode 样式目前同时在 `Andy.tsx` 运行时样式与 `NightMode` 规则两处级联——改样式前必须检查两处最终级联结果，避免只改浅色模式或重复覆盖。
- **禁止**：用 `!important` 固定浅色外观而破坏夜间模式；用硬编码颜色压主题。
- **判定方式**：浅色与深色各跑一遍 + 截图对比。

## §7 反模式清单（§2 之外的视觉反模式）

- 多栏容器灰底，间隙露出连成灰色网格（"column-gap 1px + `--cl-slate-300` 背景模拟分隔"已被判定为病根，后续改造应验证主题语义线色与边界归属，不加重背景）。
- 活动笔记同时叠底色+粗边框+阴影多个信号（选一种轻量信号即可）。
- 浅色对、夜间出现亮线/灰底/错误对比度。
- 顶部表格边框厚重，与正文争夺主次。

## §8 验收场景（合入规则，每次 UI 改造过一遍）

1. 单/双/多列：底色连续、轻量分隔、无灰底与双重边框。
2. 活动 vs 非活动列：活动易定位，非活动清晰可读。
3. 顶部区域：层级清楚，重量低于正文。
4. 浅色/夜间：语义色正确，切换无硬编码残留。
5. 窄桌面：列宽变化/滚动不重叠不跳动。
6. 键盘：焦点可见，重排/打开反馈清楚，reduced-motion 生效。
7. **截图存档作为证据**（浅色/夜间/多列/活动态），**截图不替代本规范**。

## §9 例外登记机制

任何偏离本正本的装饰/颜色/交互做法，须在 project-ledger 注册 D/e 记录（范围/依据/取舍）或在 design-rules 决策日志登记。**未登记的偏离按违规处理**（延续原 UI 禁用规则的治理红线）。
当前登记例：D-006（Andy 笔记栈导航）、D-007（顶部 Tab 唯一导航）、D-008（macOS 标题栏）。

## §10 平台与结构说明

- 本规范写的是**桌面端 NotekitDev（Andy Mode 为主的界面）**；移动端/单一页面各有独立验收流，不纳入本文管辖。
- 文档角色：规则在本文；**验收证据流水在 `notes/`**（按日期命名，快照性质会过期）；**决策台账在 `project-ledger/records/`**（只增不改带 superseded）。规则与证据不混放。
