## §1 视觉语言与定位

**主张**【项目】：让多篇笔记同一工作区像一组连续、可比较的阅读材料——**一张连续的纸面，以细线和留白组织成多个阅读列**。内容优先，容器退后：界面本身不比内容更醒目。【基础】工具类产品克制优先。
**适用条件**：Notekit 桌面端 Andy Mode 多栏阅读/编辑区；其余界面共用 token 语义但布局规则仅 Andy Mode 适用。
**判定方式**：缩小或模糊界面看一眼——视觉焦点应先落在笔记标题与正文，而非容器轮廓。
**反例**："卡片墙"——每篇笔记独立边框/阴影/圆角/灰底并排。
**忌讳**：大面积强调底色、装饰性容器堆叠、AI 生成风套路（见 §2 禁用清单）。

## §2 UI 禁用清单（负向规则，最高优先，冲突时压过本规范其他条款）

**禁止**：「圆角浅色底块 + 左侧强调色竖条」组合用作导航/列表/当前项的默认状态表达。
- **来源**：2026-10-03 用户对侧栏"豆爸的知识体系"条目的截图反馈，明确列为禁技。
- **适用边界**：禁的是该组合**及其等价变体**——换颜色、改圆角大小、竖条从阴影换边框，都算复用。不禁止圆角、背景色、分隔线本身。
- **替代取舍**：保持平面列表，状态用文字颜色、字重或既有文字标记表达；不能以"克制"为由让交互状态消失——当前项仍须可辨认，键盘焦点反馈必须保留。
- **复查范围**：仓库自带样式与运行时已加载样式；用户笔记自定义 CSS、第三方嵌入页面不据此修改。2026-10-03 全面复查已完成一轮（引用块灰底+圆角+左竖条、回收站金色左边条已清）。
- **判定方式**：人工（grep 结构性组合 + 截图目检，浅色与夜间都看）。
- 登记：project-ledger 无独立 D 号，本条〔已并入正本〕后引用一律指向 §2。

## §3 Andy Mode 交互规则

**导航模型**：列位置表达阅读路径——左 = 当前阅读上下文，右 = 从该上下文展开的内容。
1. **点击朴素链接**：来源留原位，目标紧邻右侧打开或切换；不替换来源，不跳回主区。目标右侧已有阅读路径时，切换为新目标并收起旧路径（只关视图，不删数据），不能点一次堆一篇。
2. **右侧继续点击**：沿路径 continue 向右展开，形成左→右链（A→B→C）。依据：用户 2026-10-03 明确要求（D-006 superseded 前版本已修正）。
3. **新 vs 复用**：目标已在来源右侧 → 保留目标列、收起其余后续路径；目标在来源本身或左侧 → 聚焦已有列，不建重复列。点击针对**链接所在的那一篇笔记**，不是无条件最左列。
4. **多步导航一致性**：键盘打开、链接点击、"在右侧打开"命令遵循同一来源锚点规则，不同入口不得产生相反结果。
5. **阅读位置**：点击已可见目标不自动居中；超出阅读区只滚动到最近可见边界，左侧叠放脊柱计入可用宽度。保留减少动态效果设置。
- **锚点依据**："右侧打开"是阅读模式默认导航方式，列顺序持续表达当前路径（而非窗口堆积）。同一来源点击切换右侧内容是用户 2026-10-03 显式要求。
- **判定方式**：**人手走真实点击链路**（A→B→C→回 A 点 D→得 A/D→B 点另一目标→仅替换 B 右侧）；重复点击同一目标不出空列/重复列。富文本链接的真实点击才算通过，直接调用导航命令不算。
- **例外归属**：显式新增列、重排是独立操作，不受上述导航逻辑约束。

## §4 颜色与 token

**语义 token 是唯一契约**【基础】颜色一律经变量引用，不写裸 hex。
| 用途 | 语义角色 | 约束 |
|---|---|---|
| 工作区底色 | `--nk-canvas` | 优先统一，避免列列不同底色 |
| 笔记底色 | `--nk-surface` | 笔记表面，与 canvas 区分（D-006 已拍板两色制：画布/笔记） |
| 分隔线 | `--nk-line` | 低对比度、细线；**不得用整片灰背景模拟线条** |
| 标题正文 | `--nk-ink` | 保证主题正文对比度 |
| 次级信息 | `--nk-muted` | 只承担辅助，不承担正文可读性 |
| 当前焦点 | `--nk-accent` / `--nk-accent-soft` | 少量语义化使用，不把整列染成强调色 |

- 色值唯一来源：`notekit-src/src/assets/workspace-theme.css`（主题语义来源）。正本不复制色值。
- **主题策略**：浅色 / 夜间**双主题都必须实现**（与 RTC 不同——本产品是长时间阅读工具，夜间是正式主题之一）。深色主题须使用对应暗色语义线色，不得沿用浅色硬编码。核心判断：某处看起来只在浅色下对 → 大概率有硬编码残留。
- **收欠**：旧通用名（`--primary`/`--info`/`--bgrey`/`--danger`…）降级为 `var(--nk-*)` 别名做过渡；**别名只做过渡不做长期**，每个批次迁完顺手删该别名，不制造新债。新代码一律只用 `--nk-*`。
- **判定方式**：可跑静态 grep（裸 hex、旧通用名引用计数），与验收相连。

## §5 布局

【项目】Andy Mode：
- **列宽**：桌面列 625px、正文左右 32px、标题条 40px（D-006/D-007 已拍板）；横向空间不足时滚动叠压露竖标题；800px 以下显示活动单篇。
- **分割线**：只落在相邻边界，不形成灰底板或外围框线；不得与容器边框重复叠加。顶部导航与正文有横向 1px 分割线。
- **列滚动区域彼此独立**；隐藏非活动列滚动条不得裁切内容或丢位置。
- **顶部标签/工具区应轻量**：与正文层级清楚，视觉重量低于笔记内文，不得像另一层厚重卡片。
- 列数增加时，优先保持阅读边界与焦点识别，不以加装饰补偿信息密度。

## §6 交互与动效

- **动效只解释变化**：打开/切换/重排时列边界与阅读位置稳定；不制造卡片飞入、弹跳等装饰动效。
- **遵循系统减少动态效果设置**（`prefers-reduced-motion`），基础层惯例。
- **单反例警示**：Andy Mode 样式目前同时在 `Andy.tsx` 运行时样式与 `NightMode` 规则两处级联——改样式前必须检查两处最终级联结果，避免只改浅色模式或重复覆盖。
- **禁止**：用 `!important` 固定浅色外观而破坏夜间模式；用硬编码颜色压主题。
- **判定方式**：浅色与深色各跑一遍 + 截图对比。

## §7 反模式清单（§2 之外的视觉反模式）

- 多栏容器灰底，间隙露出连成灰色网格（"column-gap 1px + `--cl-slate-300` 背景模拟分隔"已被判定为病根，后续改造应验证主题语义线色与边界归属，不加重背景）。
- 活动笔记同时叠底色+粗边框+阴影多个信号（选一种轻量信号即可）。
- 浅色对、夜间出现亮线/灰底/错误对比度。
- 顶部表格边框厚重，与正文争夺主次。

## §8 验收场景（合入规则，每次 UI 改造过一遍）

1. 单/双/多列：底色连续、轻量分隔、无灰底与双重边框。
2. 活动 vs 非活动列：活动易定位，非活动清晰可读。
3. 顶部区域：层级清楚，重量低于正文。
4. 浅色/夜间：语义色正确，切换无硬编码残留。
5. 窄桌面：列宽变化/滚动不重叠不跳动。
6. 键盘：焦点可见，重排/打开反馈清楚，reduced-motion 生效。
7. **截图存档作为证据**（浅色/夜间/多列/活动态），**截图不替代本规范**。

## §9 例外登记机制

任何偏离本正本的装饰/颜色/交互做法，须在 project-ledger 注册 D/e 记录（范围/依据/取舍）或在 design-rules 决策日志登记。**未登记的偏离按违规处理**（延续原 UI 禁用规则的治理红线）。
当前登记例：D-006（Andy 笔记栈导航）、D-007（顶部 Tab 唯一导航）、D-008（macOS 标题栏）。
